# Release Evidence

This platform is a research and engineering demonstrator. Outputs are intended for technical evaluation and human review only and must not be used for clinical diagnosis or patient-management decisions.

Milestone 13 writes generated release evidence under:

```text
reports/generated/releases/<release_id>/
```

The release manifest is assembled from the latest persisted local evidence under:

```text
reports/generated/releases/latest-evidence/
```

Manifest assembly does not rerun scanner, SBOM, image-scan, or smoke-test commands. Each upstream
command records one canonical latest result for its tool and target, and `build-release-evidence`
copies those results into the release manifest.

The directory is ignored by Git and may contain:

- `release_manifest.json`
- `image_inventory.json`
- `container_dependency_strategy.json`
- `dependency_inventory.json`
- `container_security_checks.json`
- `smoke_test_results.json`
- `checksum_manifest.json`
- `release_report.md`
- Optional SBOM files generated by Syft

The canonical tool evidence set is:

- Gitleaks repository secret scan.
- pip-audit container dependency scan.
- Syft API image SBOM.
- Syft reviewer UI image SBOM.
- Trivy API image vulnerability scan.
- Trivy reviewer UI image vulnerability scan.
- Hadolint Dockerfile lint result.

Gitleaks, pip-audit, Syft, and Trivy entries are mandatory release evidence. Hadolint is optional
advisory evidence because the internal Dockerfile validator is the mandatory Dockerfile lint gate.
If Hadolint is unavailable, the manifest records `UNAVAILABLE` with optional metadata; it is not
treated as `PASS` and does not block release status by itself.

The release manifest records git revision, dirty-tree status, build timestamp, Python version, aggregate release status, container dependency strategy, dependency versions, image names, image digests when available, image sizes in bytes when available, Dockerfile checksums, configuration checksums, scanner evidence, smoke-test evidence, and a research-only disclaimer.

Successful smoke evidence must retain `executed=true`, `status=PASS`, individual smoke steps, and
the cleanup result. A successful persisted smoke result is not replaced with a skipped placeholder
when the manifest is built.

Container dependency evidence must show that runtime images use `requirements/container-runtime.txt`, `torch==2.13.0+cpu`, and the official PyTorch CPU wheel index. Evidence must also show that CUDA/NVIDIA package inputs are prohibited.

Release evidence must not contain credentials, environment secrets, raw arrays, model weights, generated checkpoints, real patient data, or reviewer notes with identifiers.
